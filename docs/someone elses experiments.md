My [last post](https://medium.com/generative-ai-in-the-newsroom/coding-agents-for-investigative-journalism-8b65bc30f9ea) explored using Claude Code with agent skills to process and analyze structured data for investigative journalism. But for many investigations, the most valuable data sources aren’t structured at all. They’re messy collections of documents — scans without text layers, blurry pages with handwriting, redacted files, mixed formats — that resist easy processing.
The task of wrangling these kinds of documents into a usable format is both resource-intensive and essential. Consider the New York Times’ [recent description](https://www.nytimes.com/2026/02/12/insider/jeffrey-epstein-files-documents.html?unlocked_article_code=1.L1A.aWbV.lbbUZxRzuV24&smid=nytcore-ios-share) of working through millions of pages of documents from the Epstein files — dozens of journalists and technologists working around the clock to clean, organize, and begin to make sense of the material undergirding their reporting. Can AI tools help handle this grueling work in a way that’s transparent, accurate, and responsible?
I’ve been exploring that question using [agent skills](https://agentskills.io/home) across multiple coding agents, with test cases of varying size, domain, and format. I wanted to test whether coding agents could 1) produce accurate transcripts of messy documents, 2) impose useful structure on heterogeneous collections, and 3) scale to large datasets where page-by-page LLM processing isn’t economical. Across several test cases, the outputs were largely accurate and the process remained transparent and auditable, though human oversight remains essential in many areas.
For this evaluation, I selected three document sets, all used in published investigations, that have different formats, requirements, and scales:
- A collection of reports, largely handwritten, [used by Wired](https://www.wired.com/story/elon-musk-pcrm-neuralink-monkey-deaths/) to investigate primate deaths during Neuralink testing. The pages vary considerably in format and purpose, and the documents are short enough to read through. This set is a useful test case for whether LLMs can produce a legible transcript that preserves as much semantic and structural information as possible.
- A collection of [emails and other documents](https://www.documentcloud.org/documents/1339579-9-former-ag-diamond-and-nexis/) used by the New York Times as part of a [Pulitzer-winning investigation](https://www.nytimes.com/2014/10/29/us/lobbyists-bearing-gifts-pursue-attorneys-general.html) into lobbying efforts to influence attorneys general. The main challenge here is heterogeneity — the set is mostly emails, with letters and Q&As sprinkled throughout. This allows us to test the agent’s ability to structure information while handling variation in formats, page breaks, and redactions.
- A collection of New York prison employee [discipline data](https://observablehq.com/@themarshallproject/new-york-prison-employee-discipline-data) used by the Marshall Project and the [New York Times](https://www.nytimes.com/2015/12/21/nyregion/new-york-state-prisons-take-steps-to-track-complaints-about-guards.html) in a [Pulitzer finalist investigation](https://www.pulitzer.org/finalists/tom-robbins-marshall-project-and-michael-schwirtz-and-michael-winerip) in 2016. This is a dataset with a clear schema — a PDF of a spreadsheet with consistent columns — but with no text layer and redactions throughout. At hundreds of pages and thousands of records, this set would take considerable time to rectify manually.
## The skill
I designed an [agent skill](https://github.com/NHagar/agentic-investigation-documents/tree/main/.agent/skills/difficult-document-extraction) to handle these workflows. This skill encoded the principles of transparency, provenance, and human review as I explored [previously](https://generative-ai-newsroom.com/coding-agents-for-investigative-journalism-8b65bc30f9ea), but it directed the model down different paths depending on the task requirements and scale of the data. The key insight is that since coding agents are built on top of multimodal LLMs, they can read and understand images — perfect for scanned documents. The skill routes documents through one of three approaches depending on the journalist’s needs (expressed via prompting) and the scale of the data (determined programmatically via code):
**Transcription** has the model transcribe the pages of a document to corresponding markdown documents, preserving as much of the structure and layout as possible. It then stitches everything together into one markdown transcript, with indicators for where each page starts. This is the right approach when the goal is simply a legible, searchable version of a document that’s currently trapped in images or document scans.
**Structuring** extends transcription. From the initial transcript, when prompted, the model proposes a _schema_ that captures the shape of the records it identifies in the document. If the document is a ledger of expenses, for instance, the schema might have fields for the recipient’s name, the dollar amount, and whether the expense has been paid. The model presents the schema to the journalist for review, then transforms the markdown transcript into structured JSON following the finalized format. This approach is useful for documents that contain repeated record types that benefit from consistent fields (e.g., emails, filings, or transaction logs).
**Automated OCR** handles cases where a document is too long to economically process page by page with an LLM. Instead of transcribing the entire document, the LLM samples 10 pages and transcribes those. It presents its output to the journalist for corrections. From there, it writes its own OCR pipeline using [pdfplumber](https://github.com/jsvine/pdfplumber) and [tesseract](https://github.com/tesseract-ocr/tesseract), and it checks the outputs against the corrected gold standard sample provided by the journalist. Once performance has peaked or plateaued after a few iterations, the model presents a report on how well its pipeline works and what shortcomings it noted. With approval, it runs the pipeline on the full document and outputs the OCRed records. The choice of when to use this automated approach and how many pages to sample are controllable parameters specified in the skill. I chose documents 50 pages or longer and a 10-page sample, which seemed to work well, but there’s no hard rule.
## Evaluation
I ran each approach against the dataset it was designed for: the Neuralink reports with **Transcription**, the AG lobbying emails with **Structuring**, and the prison discipline records with **Automated OCR**.
I started with Claude Code, but vision performance wasn’t as good as I’d hoped. However, Gemini 3 has [state-of-the-art multimodal understanding](https://blog.google/products-and-platforms/products/gemini/gemini-3/), and it’s accessible through Google’s [Antigravity](https://antigravity.google/) IDE. Because agent skills are an open standard that works across [compatible coding agents](https://antigravity.google/docs/skills), we can cleanly carry everything over to another platform.
From there, performance was strong.

**Neuralink reports (Transcription)** posed some challenges because of the mix of handwritten and typed text — there were transcription errors and omitted fields. But overall, captured details were comprehensive, and tricky lists of values were transcribed correctly and preserved formatting and spacing.
Two drawbacks are worth noting. First, Gemini 3 was reluctant to transcribe images itself — I had to keep nudging it to avoid writing a script to perform OCR instead of using its own vision capability. ## Human review, agent-assisted
At this point, regardless of the tools used, any investigative journalist would want to stop and do a thorough manual review before proceeding. Coding agents can help here too, by generating a bespoke review interface with useful features like consistent fields, keyboard shortcuts, and page-by-page navigation to make the process less labor-intensive.
We can take this even further. In the prison disciple record test case, since the model wrote the OCR pipeline and has access to the script’s outputs, it can review everything and suggest corrections. I had Claude Code do exactly that, looking for OCR artifacts and phantom records. And then I had it integrate those suggestions into the review interface itself, so that I could easily accept or reject them. The model produced 6,900 suggestions across records. They don’t catch every issue, but across 10 pages of records that I manually reviewed, the corrections suggested were all valid.

## Limitations
This work builds on the hard labor of journalists who tracked down newsworthy information and made FOIA requests to surface these documents. The coding agent is a tool, not an investigative reporter.
LLM transcription is very good, but it’s not OCR in the traditional sense. The LLM can fabricate text in unpredictable ways that have nothing to do with the underlying document text. This is a fundamentally different failure mode from conventional OCR, which might misread a character but won’t invent a sentence.
And there is a substantial amount of human judgment involved throughout this workflow: deciding what a good-enough transcript looks like, reviewing schemas, correcting outputs. Automation can’t replace the careful considerations and tradeoffs that a journalist must take into account when working through an investigation.
## Looking forward
Coding agents show real promise in assisting with some of the most time-intensive, and least rewarding, parts of investigations. If an AI agent can meaningfully speed up the process of cleaning and standardizing data, reporters can spend more time digging through records and building a story. That unlocks time to explore other angles, go deeper, find additional sources — time that would have otherwise been spent processing documents.
You could also imagine chaining these steps together. Once the data is cleaned, you could plug the structured output into the skill from the last post to run preliminary analyses and surface patterns worth investigating. To enable that kind of experimentation, I’ve open sourced the [repo](https://github.com/NHagar/agentic-investigation-documents) from this evaluation, and I’ve added the document ingestion skill to my [investigative skills library](https://github.com/NHagar/claude-plugins-journalism) on GitHub.
The promise is not that an AI can replace an expert investigator. Rather, it’s becoming clear that coding agents are versatile tools for handling a range of labor-intensive tasks under the supervision of an expert human.
